# 两条线说明 · 自用线 vs 公开线（2026-10-25 起）

ArkBox 在本机是**一份代码、两条使用线**，互相独立、单向同步。

## 结构

```
~/Documents/Projects/arknights-arkbox/   ← 公开线（GitHub: chenzefeng0731/arkbox）
   代码 + fixtures + 演示产物 + 文档
   本地目录名保持 arknights-arkbox 不改（历史引用不断链）；GitHub 仓库名为 arkbox
   永远不含：真实昵称 / UID / 凭证 / 真实抽卡记录 / 发布状态

~/.qoder-cn/skills/arkbox/               ← 自用线（Qoder 里日常用的 skill）
   由 install.py 从公开线复制，是你对话入口「用 arkbox …」的执行体

~/.arkbox/                               ← 数据层（两条线共享，永不进仓库）
   credentials.json   登录态（600 权限）
   archive/<uid>/     真实寻访档案
   cache/             卡池表 / 干员元数据
   reports/           海报 PNG / 报告 HTML 都落这里
```

## 各自怎么用

- **自用（要登录、要真实数据）**：直接在 Qoder 里说「用 arkbox 分析我的抽卡 /
  出海报 / 更新我的站点」。走安装目录，读 `~/.arkbox` 登录态，产物写 `~/.arkbox/reports/`。
- **公开（给外网用户）**：仓库代码 + `fixtures/demo-records.jsonl`（复刻真实档案结构、
  时间轴平移 180 天、无账号信息）。`docs/演示产物/` 是当前 demo 效果样例。

## 同步规则（单向：公开线 → 自用线）

代码改动一律在**仓库里改**（公开线是唯一源码），然后：

```bash
cd ~/Documents/Projects/arknights-arkbox
python3 install.py --target qoder --force   # 复制并自动跑 selftest
```

不要直接改 `~/.qoder-cn/skills/arkbox/` 里的文件——下次 install 会覆盖丢失。

## 为什么公开线跑不脏

在仓库目录里跑任何命令都不会把真实数据带进可提交区：

- `--html` / `--poster` 产物写 `~/.arkbox/reports/`（仓库外）；
- `--site` 写 `site/`、`fetch --out` 默认写 `gacha_records.json`——两者都在 `.gitignore`；
- 登录态与档案在 `~/.arkbox/`，不在仓库树内。

历史上含真实昵称的验收产物已整体移至
`~/Documents/Projects/历史归档/arkbox-真实账号产物-2026-10-25/`。

## demo 的保真度

`fixtures/demo-records.jsonl` 是真实档案的结构复刻：294 抽 / 10 六星 / 3 池 /
间隔结构一致，因此 demo 海报与报告的数字、称号（双金还债）、池型、UP 判定
和真实版一致；区别只有昵称（演示博士）、入职日期（`--tenure` 传入）与整体
平移 180 天的时间轴。重新生成演示产物：

```bash
python3 skill/arkbox/scripts/ark_gacha.py analyze \
  --records fixtures/demo-records.jsonl --nick 演示博士 --tenure 2023-01-15 \
  --poster --html --quiet
```
