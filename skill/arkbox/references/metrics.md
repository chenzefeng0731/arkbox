# ArkBox 数据口径与称号规则（v0.6 P1/P2）

本文件是三形态（对话 Markdown / HTML 报告 / 分享海报）的唯一口径说明。
代码入口：`ark_report.build_report()`；概率入口：`ark_odds.py`。

## 1. 官方六星规则（2026-10 核验）

- 六星基础出率 **2%**；
- 连续 **50 抽**未出六星后，第 **51 抽**起每抽 **+2%**；
- 第 **99 抽**必出（硬保底）；
- 出六星后计数重置。
- 官方计数规则：标准/中坚的六星计数跨同类型卡池累计；限定寻访当期结束清零；
  联动/特殊按当期公告。**UP 保底/天井是另一套规则**。
- 本工具默认**不跨池合并**：森空岛只返回可查窗口内的记录，无法证明更早的
  标准/中坚历史完整。跨池首段可能承接未知垫抽，因此按池独立统计，
  每池从档案内第一条记录起算，并标注首段可能不完整。

理论期望：**34.59 抽/六星**。中位数约 35 抽。

旧版本曾写「62 抽硬保底」，是错误参数；已修正。旧模型期望 34.44，
在本批数据（没有超过 62 的已完成间隔）上数值接近，但长空窗会算错。

## 2. 四个必须分开的指标

| 指标 | 公式 | 含不含未结算抽 | 用途 |
|---|---|---|---|
| 本区间抽数 | Σ 各池抽数 | — | 总量 |
| 六星干员 | Σ 各池六星数 | — | 总量 |
| 池内间隔均值（主值） | Σ各池可见间隔 ÷ 段数 | **不含当前垫抽** | 海报大数字、理论位置 |
| 整体效率 | 本区间抽数 ÷ 六星数 | **含当前垫抽** | 解释“为什么不是 294÷10” |
| 六星垫抽（按池） | 每池 `总抽数 - 最后六星位置` | — | 当前状态；各池独立，不跨池合并 |
| 最长池内间隔 | `max(各池可见间隔)` | **不含当前垫抽** | 蓝色横幅；第 N 抽就是出货抽 |

恒等式（`verify_report()` 会检查）：

```
Σ池内间隔 + Σ池内垫抽 = 本区间抽数
池内间隔均值 = Σ池内间隔 ÷ 间隔段数
整体效率 = 本区间抽数 ÷ 六星数
```

注意：每池第一条可见记录之前可能还有历史，所以“池内间隔”不等于严格的
“从 0 垫到出货”。工具在审计表和 HTML 里标注“首段自档案首条记录起算”，
不把这段当成已证明完整。

**“N 连抽未出”要慎用**：间隔 60 抽表示第 60 抽就是六星，严格说是
“连续 59 抽未见、第 60 抽出货”。当前垫抽 限定 41 / 联动 17 / 标准 2
是三个池各自的“还没出”，不能相加成一次 60 连；60 只是合计，只用于核对
“间隔 + 垫抽 = 总抽数”。

## 3. 理论位置（不是全服排名）

- 单段间隔分布：`ark_odds.six_star_pmf()`。
- n 段均值分布：n 个独立间隔之和的分布；n≤25 用精确卷积，n>25 用正态近似。
- 观测均值 `m` 的理论位置：

```
better_than = 1 - P(理论均值 <= m)
```

含义：**优于约 better_than% 的同段数理论样本**。越高越欧。
主值用按池独立的可见间隔，不做跨池合并。
例：10 段、合计 234、均值 23.4 → **优于约 95.3%**。
这个数字没有校正“各池首段可能承接档案外垫抽”的偏差；它回答的是
“这 10 段可见间隔有多欧”，不是“账号生涯真实分布”。

禁止写成“全服前 X%”“超越 X% 博士”“真实排名”。

旧版 36.6% 的问题：
1. 它是 10 个单段分位的算术平均（分位的平均），不是平均间隔的分位；
2. “优于约 36.6%”方向反了（CDF=36.6% 表示 36.6% 的单段更短）。
因此 v0.5 不再输出 `avg_percentile`。

## 4. 称号：固定评级 + 事件副签

原则：**主称号永远是对博士的固定评级**（零阶解码），事件一律降为 caption /
副签 / 备选。不造书面比喻，不用过时的泛抽卡梗（如“海豹”）。所有称号由数据
规则生成，不写死故事。

2026-10 玩家反馈修订：①“双金还债”需二阶解码、“还债”AI 味重，退出称号体系；
②主称号必须是评级（如“欧皇”），不能是事件句。

主称号（固定评级）：

1. 无记录 → **档案新建**
2. 有记录但无六星 → **零金**
3. 任一池 ≥300 抽 → **吃井**（档案状态级事件，保留）
4. 按理论位置：≥90 **欧皇** / 70–90 **小欧** / 20–70 **正常发挥** / 5–20 **小非** / <5 **大非酋**
   - caption：有事件时讲事件（按下表优先级取第一句），无事件时给评级依据
     「N 段均值 X 抽，理论优于 Y%」

事件优先级（降为 caption 与候选，顺序即讲故事顺序）：

1. 最佳十连 ≥2 金：
   - 有长空窗（最长≥50 或当前垫≥50）→ caption「{pool} {n} 抽{N}金，但 {gap} 抽才出」，
     候选「{双/三/…}金，但 {gap} 抽才出」
   - 无长空窗且 ≥3 金 → 候选「{三/四/…}金血赚」
   - 无长空窗且 2 金 → 候选「双金」
2. UP 全中（≥3 次）→ 候选「不歪拿下」；UP 全歪（≥3 次）→ 候选「歪麻了」
3. 同一六星 ≥3 次 → 候选「三顾茅庐」
4. 长空窗 → 候选「保底人」；单池连歪 ≥2 → 候选「连歪 N 次」
5. 到井 → 候选「吃井」

小标签（来自真实数据）：
`双金`、`三金`、`{N} 抽才出`、`三顾茅庐`、`垫刀 N`、`UP x/y`、`歪 N`、
`吃井`、`零金`。十连结果用“金”，不用旧的“双黄”。

边界：称号只负责评级，事件只负责讲故事；海报保留“理论模型 / 非全服排名”。

当前真实档案（示例）：
294 抽 / 10 六星 / 池内 10 段：23.4 / 95.3% /
整体 29.4 / 六星垫 限定 41 + 联动 17 + 标准 2（各池独立） /
最长池内间隔 60（第 60 抽出）/ 最佳十连 海渊 10 抽双金
→ 主称号 **欧皇**；caption「海渊巡游 10 抽双金，但石白深蓝之夜 60 抽才出」；
候选含「双金，但 60 抽才出 / 双金 / 三顾茅庐 / 保底人」。

## 5. 覆盖范围

- 默认：**本档案区间（仅部分历史，完整性未知）**。
- 有同步失败或分页截断：**已知缺口**。
- 只有调用方拿到可验证的全历史依据时才标 **完整连续**。
- 删除“生涯”“全量”等暗示账号全历史的词。
- 官方接口不提供账号全历史证明，因此默认不标完整。

## 6. 隐私

- 分享海报/HTML 默认 UID **中间遮挡**（前 3 后 2），昵称保留。
- `--privacy full|mask|hide`；`--hide-nick` 单独隐藏昵称。
- 海报 HTML 不落完整 UID；条码只作装饰，seed 不含 UID。
- 本地原始档案 `~/.arkbox/archive/` 不受影响；`--privacy full` 才在产物里
  显示完整 UID。

## 7. 池型、保底与 UP

- 池型：限定 / 中坚 / 联动 / 标准 / 特殊 / 待核。
- 「限定」只认 `limitedChar` 或官方 `RATE_UP_6` 文案里的“限定寻访”；
  **单 UP ≠ 限定**（联动池也常是单 UP）。
- 官方六星计数：标准/中坚同类型跨池累计；限定/联动/特殊按当期各自域。
  这是规则说明，**不是本工具的默认计算方式**。
- 本工具默认按池独立：不合并标准/中坚跨池垫抽，因为官方接口无法证明
  更早历史完整。每池首段从档案内首条记录起算，可能承接档案外垫抽。
- UP 命中 = 六星 charId 是否在当期六星 UP 名单里；无法匹配时标“待核”，
  不硬判，也不把待核池算进总命中率分母。
- UP 保底/兑换天井（120/150/300 等）是另一套规则，不能和“六星垫 2/99”混用。
- 兑换井进度：限定按 300、联动按 120，显示 `档案内当期抽数 / 井`；
  标准/中坚/特殊规则不统一，不硬算。进度只作参考，以游戏内公告为准。
- 数据源：PRTS `gacha_table.json` 镜像；缓存 v3。

## 8. 数据完整性实测（2026-10-25）

森空岛/官网只返回可查窗口内的卡池目录与记录；本次只读审计结果：

| 官方目录 | 池 | 记录数 | 区间 |
|---|---|---:|---|
| `summer_fest` 限定寻访·夏季 | 车辙与风的归所 | 201 | 2026-08-01 ~ 08-14 |
| `P3R_01` 圣城春日学生寻访 | 石白深蓝之夜 | 83 | 2026-09-04 ~ 09-13 |
| `normal` 标准寻访 | 海渊巡游 | 10 | 2026-10-09 |

- 合计 3 个目录 / 294 条；标准目录 `normal` 只有海渊巡游 10 条。
- **无法证明** 2026-08-01 之前没有标准垫抽，也无法证明更早的标准/中坚池
  没有留下计数。因此**不做跨池累计**：海渊只按本池 10 条记录计算。
- 默认主值：按池独立 10 段 / 合计 234 / 均值 23.4 / 理论位置 95.3%；
  首段可能承接档案外垫抽，这是已声明的偏差，不藏。
- 当前垫抽：限定 41 / 联动 17 / 标准 2，各池独立；合计 60 只用于核对总数。
- `analyze --audit` 和 HTML 报告会列出每个池的抽数、六星、池内均值、
  当前垫、记录范围和首段说明；用户可自行核对。

官方规则口径：标准寻访 6★ 计数跨标准池累计，出 6★ 重置；中坚独立；限定当期结束清零；联动/特殊按当期公告。参考游戏内【寻访规则】与公开规则整理（[萌娘百科·保底](https://mobile.moegirl.org.cn/%E4%BF%9D%E5%BA%95)、[官方限定寻访公告](https://ak.hypergryph.com/news/4916)）。


## 9. 分享文案与 HTML 交互

`report["share"]` 提供三段可直接复制的文案：

1. **主文案**：称号 + 抽数/六星 + 池内均值 + 最佳十连 + 最长间隔 + UP + 理论位置；
2. **数据版**：抽数 / 六星 / 池内均值 / 理论位置 / UP / 最长间隔；
3. **短句**：称号 + 三个核心数字。

三段都带 `#明日方舟 #寻访档案 #ArkBox`，不含完整 UID。
HTML 的“换个说法”可切换称号候选，“分享文案”可切换文案并复制；
海报是静态图，使用主称号与主文案的视觉版本。

`report["data_gaps"]` 会把历史区间未知、同步失败、分页截断、标准/中坚垫抽
不可追溯、首段偏差、未计算兑换井的池型列出来；HTML 用卡片展示，不藏在脚注。

## 10. 离线输入

`analyze --records <json|jsonl> [--nick] [--uid]` 直接分析本地记录，
不扫码、不写归档，覆盖标签仍默认“本档案区间（仅部分历史，完整性未知）”。
适合其他来源导出的记录、朋友发来的 JSON，或调试渲染器。


## 11. 入职信息

- 只读取 `player/info` 的 `status.registerTs`，在 HTML/站点页头 UID 后展示
  `入职 YYYY-MM-DD · N 天`。
- 不展示助战、干员、阵营、基建、理智、最后在线等玩家数据；这些模块已移除。
- 离线记录或档案读取失败时隐藏，不影响抽卡报告。
- 抽卡海报不带入职信息。
